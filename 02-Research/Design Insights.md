# 💡 Design Insights

ข้อสังเกตเชิงออกแบบที่สรุปได้จาก [[Feature Matrix]] และ benchmark ทั้งหมด

## 1. ปัญหาใหญ่สุดคือ "ข้อมูลตาย"
ศิษย์เก่ากรอกครั้งเดียวแล้วไม่กลับมาอัปเดต Entaneer แก้ด้วยการโชว์ **"อัปเดตเมื่อ"** ให้เห็นความสดของข้อมูล
→ รายละเอียดวิธีแก้ที่ [[Engagement Strategy]]

## 2. PDPA เป็นความเสี่ยงจริง
Directory ที่เปิดสาธารณะ = เปิดเผยข้อมูลส่วนบุคคล
- ต้องมี consent ตอนสมัคร
- ตั้งค่าความเป็นส่วนตัว **รายฟิลด์** (เบอร์/อีเมล/บริษัท)
- บังคับ login ก่อนดูข้อมูลติดต่อ (ลอก Entaneer)
→ [[PDPA and Privacy]]

## 3. อย่าให้กรอกซ้ำ
Seed ข้อมูลจากทะเบียน/CONGRATE แล้วให้ศิษย์เก่า **"claim profile"** ด้วย รหัสนักศึกษา + เลขบัตรประชาชน/วันเกิด
→ ได้ฐานข้อมูลเต็มตั้งแต่วันแรก แทนที่จะเริ่มจากศูนย์
→ นี่คือข้อได้เปรียบที่ระบบสมัครสมาชิกแบบเดิมทำไม่ได้

## 4. LINE คือช่องทางจริง
ทุกเว็บที่สำรวจใช้ LINE OA เป็นช่องทางหลัก (NU ใช้แจ้งชำระเงินด้วยซ้ำ)
→ วางแผน **LINE Login + Messaging API** ตั้งแต่ต้น engagement สูงกว่า email มาก
→ [[Architecture]]

## 5. Social proof ด้วยตัวเลข
NU โชว์ "31 ปี / 8 สาขา / 2,824 คน", Entaneer โชว์ "15,537 สมาชิก"
→ ทำง่าย ได้ผลด้านความน่าเชื่อถือ ใส่ในหน้าแรกตั้งแต่ MVP

## 6. อย่าสร้างสิ่งที่มหาวิทยาลัยมีแล้ว
ขอ transcript/ใบรับรอง → ลิงก์ไปสำนักทะเบียน (ธรรมศาสตร์ทำแบบนี้)
โฟกัสที่สิ่งที่คณะทำได้ดีกว่า: ความสัมพันธ์ในสาขา, งาน, mentor
