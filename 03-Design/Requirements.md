# 📋 Requirements (v0 — ร่างจาก research)

ที่มา: [[Feature Matrix]] + [[Design Insights]] · **ยังต้องยืนยันกับผู้มีส่วนได้ส่วนเสีย**

รหัส: `FR` = functional · `NFR` = non-functional · ลำดับ: `M` must / `S` should / `C` could

## Functional

| ID | ความต้องการ | ลำดับ |
|---|---|:--:|
| FR-01 | นำเข้าข้อมูลศิษย์เก่าตั้งต้นจากทะเบียน/CONGRATE | M |
| FR-02 | ศิษย์เก่ายืนยันตัวตนและ claim โปรไฟล์ (รหัส นศ. + วันเกิด/บัตร ปชช.) | M |
| FR-03 | แก้ไขโปรไฟล์ตนเอง + ตั้งค่าความเป็นส่วนตัวรายฟิลด์ | M |
| FR-04 | แสดง "อัปเดตข้อมูลเมื่อ" และความสมบูรณ์ของโปรไฟล์ | M |
| FR-05 | ค้นหาศิษย์เก่าแบบ faceted (รุ่น/สาขา/จังหวัด/บริษัท/ตำแหน่ง/ทักษะ) | M |
| FR-06 | ทำเนียบรุ่น + สถิติภาพรวม (จำนวนปี/สาขา/คน) | M |
| FR-07 | ข่าวสาร/ประชาสัมพันธ์ (CMS) | M |
| FR-08 | ปฏิทินกิจกรรม + ลงทะเบียนร่วมงาน | S |
| FR-09 | Job board — ศิษย์เก่าโพสต์งาน/ฝึกงาน | S |
| FR-10 | แบบสำรวจภาวะการมีงานทำ + dashboard QA | S |
| FR-11 | ศิษย์เก่าดีเด่น + ระบบเสนอชื่อ | S |
| FR-12 | Gallery ภาพกิจกรรม | S |
| FR-13 | แจ้งเตือน/broadcast ผ่าน LINE OA | S |
| FR-14 | บัตรศิษย์เก่าดิจิทัล (QR) | C |
| FR-15 | จองของที่ระลึก/เสื้อคืนเหย้า | C |
| FR-16 | ระบบสมาชิกสมาคม + ประวัติการชำระเงิน | C |
| FR-17 | Mentorship matching รุ่นพี่–รุ่นน้อง | C |
| FR-18 | Admin: จัดการผู้ใช้ เนื้อหา และ export รายงาน | M |

## Non-functional

| ID | ความต้องการ |
|---|---|
| NFR-01 | สอดคล้อง **PDPA** — consent, สิทธิเจ้าของข้อมูล, audit log → [[PDPA and Privacy]] |
| NFR-02 | Mobile-first / responsive (ศิษย์เก่าเข้าผ่านมือถือเป็นหลัก) |
| NFR-03 | รองรับภาษาไทยเต็มรูปแบบ (เรียงลำดับ, ค้นหา, คำนำหน้าชื่อ) |
| NFR-04 | ข้อมูลติดต่อต้อง login ก่อนดู + ป้องกัน scraping / rate limit |
| NFR-05 | ดูแลรักษาได้หลังส่งมอบ — เอกสาร, backup, ผู้รับผิดชอบชัดเจน (บทเรียนจาก [[Benchmark - KSU]]) |
| NFR-06 | รองรับผู้ใช้พร้อมกันระดับ peak ช่วงงานคืนเหย้า |
